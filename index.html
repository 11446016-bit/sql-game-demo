01｜案例背景

本系統提供給遊戲玩家與社群管理者使用。當玩家收藏許多角色時，容易忘記角色屬性、稀有度與擁有狀態。本資料庫將玩家、角色與收藏紀錄分開儲存，讓使用者查詢角色清單、篩選稀有角色、統計收藏數量，並比較不同查詢條件的結果。

02｜資料庫設計（ERD）

關聯：players（1）→（多）collections（多）←（1）characters。collections 為連接表，實現玩家與角色的多對多關係。

player_name TEXT NOT NULL
level INTEGER NOT NULL
collections 收藏紀錄
🔑 collection_id INTEGER PK

04｜同一問題的 SQL 結果比較

問題：找出玩家「小明」擁有的角色。比較「全部角色」與「只顯示五星角色」。

原始 SQL：全部收藏

SELECT c.character_name, c.rarity
FROM collections AS co
JOIN players AS p
  ON co.player_id = p.player_id
JOIN characters AS c
  ON co.character_id = c.character_id
WHERE p.player_name = '小明'
ORDER BY c.rarity DESC;

修改 SQL：只看五星

SELECT c.character_name, c.rarity
FROM collections AS co
JOIN players AS p
  ON co.player_id = p.player_id
JOIN characters AS c
  ON co.character_id = c.character_id
WHERE p.player_name = '小明'
  AND c.rarity = 5
ORDER BY c.rarity DESC;

預期差異：原始查詢會顯示小明的 3 個角色（蒼焰騎士、星海巫女、森林守衛）；新增 AND c.rarity = 5 後只剩 2 個五星角色。原因是 WHERE 多了一個篩選條件，排除了四星角色。

05｜設計與 SQL 重點

主鍵 PK：唯一辨識資料外鍵 FK：建立資料表關聯JOIN：合併關聯資料WHERE：篩選資料GROUP BY：分組統計ORDER BY：排序

將玩家與角色資料分表，可減少重複資料；collections 只記錄玩家與角色的關係。執行錯誤 SQL 時，頁面會顯示 SQLite 回傳的錯誤資訊。重新整理或按「重設資料庫」可恢復原始樣本資料。
